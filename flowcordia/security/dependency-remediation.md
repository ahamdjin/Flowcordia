# Dependency remediation boundary

## Result

The first complete OSV scan of the root pnpm workspace reported 120 vulnerable package occurrences, including 69 high-or-critical occurrences. This remediation updates the direct selections and transitive resolution boundaries that can be changed safely before Private Beta and reduces the exception-aware current-lockfile scan to zero unreviewed findings.

The remediation is not a blanket package refresh. It preserves the repository's three-day minimum release age, keeps the existing patched dependencies, and requires the complete repository build and test matrix before merge.

## Maintained dependency changes

- `@kubernetes/client-node` moves from the old `0.20.x` line to `1.4.0`. The provider source is migrated to the maintained request-object API and direct response bodies. Provider typechecking is a dedicated blocking gate.
- Remix packages used by the webapp move from `2.17.4` to `2.17.5`.
- DOMPurify moves to `3.4.12`.
- Bounded pnpm overrides select fixed releases for affected Vite, Webpack, `file-type`, `body-parser`, DOMPurify, `fast-uri`, Hono, Fastify static serving and Remix router dependency paths.
- Turborepo remains on the repository-compatible 1.x configuration line. An automatic audit proposal attempted to force Turbo 2 without migrating `turbo.json`; the full matrix rejected that major jump. Turbo 2 migration is therefore a separate compatibility change rather than a hidden transitive override.
- OpenTelemetry stable packages remain aligned on their compatible release families. Forcing only `@opentelemetry/core` to 2.8 while `sdk-trace-base` remained on 1.30 caused the webapp to fail at startup; the incompatible override is prohibited and the complete SDK 2 migration remains explicit work.

The lockfile is generated by pnpm. It is never edited manually.

## Reviewed exceptions

All exceptions live in `osv-scanner.toml`, identify exact GHSA advisories, contain a specific reason and have an expiry date. The permanent policy gate rejects duplicate IDs, unexpected additions, missing reasons, expired entries, entries lasting more than 90 days and broad package-level exceptions.

## Enforced checks

Every relevant pull request now runs:

1. raw OSV comparison between the base and head lockfiles, so a new occurrence cannot hide behind the existing exception file;
2. an exception-aware full scan of the proposed head lockfile;
3. strict TOML exception validation using Python's standard `tomllib` parser;
4. exact dependency-selection assertions, including bans on Turbo and OpenTelemetry core major overrides;
5. enforced Turbo 1 workarounds: no `.yarnrc.yml`, `turbo login` or `turbo sso` usage;
6. enforced OpenTelemetry 1.30 workarounds: no raised Node header-size flag and no custom W3C baggage propagator in application source;
7. database generation/build and Kubernetes provider typechecking against the maintained client;
8. the repository's normal formatting, lint, TypeScript, build, E2E and unit matrix.

Scheduled and `main` OSV scans use the same reviewed configuration and fail when an exception expires or any additional vulnerability appears.

## Evidence interpretation

The baseline counts came from the first root-lockfile OSV campaign run. The permanent source of truth is the checked-in lockfile plus current scanner artifacts, not the historical count. When advisory data changes, the current OSV run supersedes the original baseline. The final graph must also prove Turbo 1 generation compatibility, OpenTelemetry 1.30 startup compatibility and Kubernetes client 1.4 type compatibility before this record is accepted.

The compatibility strategy is intentionally split: this PR removes safely remediable findings while incompatible AI SDK, Remix router, Turbo and OpenTelemetry major migrations remain explicit, expiring work instead of being disguised as transitive overrides.

## Honest limit

This remediation proves the checked lockfile has no OSV finding outside the nine explicit, expiring exceptions at scan time. It does not prove that advisory databases are complete, that every vulnerable function is reachable, that no unknown vulnerability exists, or that static dependency analysis replaces runtime security testing and incident response.
